# Автопошук можливостей для лікарні

Щодня о 12:00 за Києвом GitHub сам запускає скрипт. Він шукає гранти, програми ЄС (Horizon Europe, EU4Health), запрошення до партнерств, стажування, майстер-класи, курси та новини про допомогу медзакладам. Нове приходить листом на всі вказані адреси, а загальна картина видна на дашборді. Усе безкоштовно.

## Налаштування (один раз)

### 1. Репозиторій
1. На github.com створіть репозиторій (**New repository**) і оберіть **Public**. Безкоштовні GitHub Pages працюють лише з публічними репозиторіями. У репозиторії немає нічого секретного: пароль і адреси пошт зберігаються в Secrets (крок 2), а в файлах лише відкриті пошукові запити та знайдені публічні оголошення.
2. Завантажте файли: `find_opportunities.py`, `build_dashboard.py`, `send_email.py`, `config.json`, `seen.json`, `README.md` (**Add file → Upload files**) і папку `docs` із двома файлами всередині (`index.html`, `data.json`).
3. Створіть файл `.github/workflows/daily.yml` через **Add file → Create new file**: у полі імені введіть цей шлях, скісні риски створять папки. Вставте вміст файлу `daily.yml` з архіву.

### 2. Листи на кілька пошт
Листи надсилаються з вашої Gmail-пошти через пароль застосунку.

1. У Google-акаунті має бути ввімкнена двоетапна перевірка (myaccount.google.com → Безпека).
2. Створіть пароль застосунку: myaccount.google.com/apppasswords. Скопіюйте 16 символів.
3. У репозиторії: **Settings → Secrets and variables → Actions → New repository secret**. Додайте три секрети:
   - `MAIL_USER`: ваша адреса Gmail, з якої надсилаємо;
   - `MAIL_APP_PASSWORD`: пароль застосунку з кроку 2 (не звичайний пароль від пошти);
   - `MAIL_TO`: адреси отримувачів через кому, без пробілів, наприклад `kyrylova.zokl@gmail.com,fomenko.zokl@gmail.com,bilyavska.zokl@gmail.com`. Додайте туди й свою адресу, якщо потрібен лист і вам.

Поки секрети не додано, замість листа створюється Issue на GitHub, і про нього повідомляє лише власник репозиторію.

### 3. Дашборд
1. **Settings → Pages**. У розділі Build and deployment оберіть Source: **Deploy from a branch**, Branch: **main**, папка **/docs**. Натисніть Save.
2. Адреса дашборда: `https://ВАШ-ЛОГІН.github.io/НАЗВА-РЕПОЗИТОРІЮ/`. Вона ж буде в кожному листі.
3. Після першого запуску пошуку (крок 4) дашборд наповниться, зазвичай протягом кількох хвилин.

### 4. Перший запуск
**Actions → Щоденний пошук можливостей для лікарні → Run workflow**. Так ви перевіряєте все одразу, не чекаючи 12:00.

## Розклад
GitHub рахує час за UTC і не переходить на літній час, тому в `daily.yml` два розклади (09:00 і 10:00 UTC), а скрипт сам пропускає той, що не припадає на 12:00 за Києвом. GitHub може запускати завдання із запізненням у кілька хвилин, а за великого навантаження й довше. Зміна часу робиться в рядках `cron` і в перевірці години `12` у кроці «Перевірка часу».

## Що шукає
Запис потрапляє у результат, лише якщо в ньому є і медична тема (`topic`), і ознака можливості (`kind`: грант, конкурс, навчання, курс, стажування, партнерство, Horizon, обладнання тощо), і немає слів зі списку `exclude`. Кожен запис отримує категорію: Horizon Europe та програми ЄС, партнерства й консорціуми, навчання й стажування, гранти й конкурси, допомога організацій.

Джерела у `config.json`:
- `feeds`: стрічки RSS сайтів;
- `news_queries`: запити Google News українською й англійською. Тут же ловляться новини про те, які фонди й організації передають обладнання лікарням, і оголошення на кшталт «лікарня шукає партнерів»;
- `pages`: сторінки установ і донорів без RSS. Скрипт повідомляє про нові посилання на них;
- `telegram`: назви публічних каналів без @. Список порожній, впишіть свої.

## LinkedIn, Facebook, Instagram
Ці мережі закривають доступ скриптам і вимагають вхід в акаунт, тому автоматично вони не читаються. Налаштуйте вручну: підписку на сторінки донорів із дзвіночком і збережений пошук у LinkedIn, наприклад за фразами «call for proposals Ukraine health» та «partner search hospital». Цікаве додавайте в трекер.

## Важливо
- Скрипт знаходить оголошення, але не читає умови й дедлайни. Відкрийте посилання й перевірте, чи ваш заклад може бути заявником.
- Джерела, які не відкрилися під час запуску, показані на дашборді в розділі про нові записи за 30 днів.
- Якщо результатів забагато чи замало, змінюйте `topic`, `kind` і `exclude` у `config.json`.
