# Автопошук можливостей для лікарні

Раз на тиждень (понеділок, 06:00 UTC) GitHub сам запускає скрипт. Він читає стрічки грантових сайтів і новинні запити, лишає записи про медицину й охорону здоров'я і створює Issue зі списком нового. GitHub надсилає вам лист про цей Issue. Усе безкоштовно, свій сервер не потрібен.

## Налаштування (приблизно 10 хвилин, один раз)

1. Зареєструйтеся на github.com (безкоштовно) і натисніть **New repository**. Назва будь-яка, наприклад `hospital-opportunities`. Оберіть **Private**, щоб репозиторій бачили тільки ви.
2. Завантажте в репозиторій усі файли з цього архіву разом із папкою `.github`: **Add file → Upload files**. Папка `.github` прихована на деяких системах. Якщо вона не видна, у Windows увімкніть показ прихованих файлів, у macOS натисніть Cmd+Shift+крапка.
3. Відкрийте вкладку **Actions** і, якщо потрібно, натисніть **I understand my workflows, enable them**.
4. Щоб перевірити одразу, а не чекати понеділка: **Actions → Пошук можливостей для лікарні → Run workflow**.
5. Щоб листи точно приходили: у репозиторії натисніть **Watch → All activity**.

Перший запуск може дати більше записів, ніж зазвичай, бо стрічки ще не «бачені». Далі приходитимуть лише нові.

## Як це змінити

Усе налаштовується у файлі `config.json`:

- `feeds` — стрічки RSS. Додайте сайт, якщо він має RSS (адреса зазвичай закінчується на `/feed/` або `/rss/`).
- `news_queries` — пошукові запити для Google News. Додайте свої: профіль лікарні, потрібне обладнання, назви донорів.
- `include` — ключові слова: запис потрапляє у список, якщо містить хоча б одне. Пишіть основу слова, щоб ловити всі форми (`лікар` знайде лікарня, лікарні, лікарень).
- `exclude` — слова, які відсіюють запис (наприклад, `вакансі`).
- `max_age_days` — скільки днів вважати запис свіжим.

Щоб змінити день чи час, відредагуйте рядок `cron` у `.github/workflows/weekly.yml`.

## Що важливо знати

- Скрипт знаходить оголошення, але не читає умови й дедлайни. Відкрийте посилання й перевірте, чи ваша лікарня (її юридична форма, регіон, сума) підходить.
- Якщо якесь джерело перестане працювати, у наступному Issue буде рядок «Не вдалося прочитати стрічки» з назвою джерела.
- Список уже побачених записів зберігається у `seen.json`. Скрипт сам оновлює його після кожного запуску.
